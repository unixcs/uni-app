# 生产数据初始化与域名切换

## Goal
从本地生成经过验证的干净业务基线，部署第一个完整生产版本到 B，并完成不依赖本地配置的生产验收。

## Requirements
- 白名单保留商品/SKU/分类/页面/系统配置/必要图片；清空用户/OAuth/订单/退款/支付/余额/反馈/队列/日志。
- 新生产 DB/user/admin/store 密码；正式 env/payment 资料独立保护，歧义配置不得猜测。
- 初始化脚本与日常迁移严格分离；导入前后有计数、引用和 checksum 验证。
- 发布到候选目录，内部检查后原子激活；B 全部健康前不撤维护页。
- 正式业务/回调统一 B；A 仅本地测试。后端兼容旧客户端。

## Acceptance Criteria
- [x] 生产交易/用户测试表为空，11 个商品等白名单数据和引用图片完整。
- [x] env/uploads/payment/DB 位于共享/独立存储且不会被发布覆盖。
- [x] B 的 health/H5/API/admin/store/uploads/回调路径和 HTTPS 通过。
- [x] Timer 在观察窗口稳定，无 crash storm/异常日志增长。
- [x] 代码回滚演练不损失生产基线，维护页仅在全绿后撤除。
- [x] 体验版指向 B 的最终验收步骤和正式发布说明完成。
