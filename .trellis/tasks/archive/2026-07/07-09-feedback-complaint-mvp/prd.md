# Feedback and complaint MVP

## Goal

交付一个最小可用的反馈 / 投诉闭环：
- 用户可在小程序提交反馈或投诉；
- 用户可查看自己的反馈记录、处理状态与官方回复；
- 商家后台可按类型/状态筛选记录，维护状态并编辑官方回复；
- `投诉反馈` 在同一套记录内可被单独归类处理。

## Confirmed facts

- 现有上传能力已存在，可直接复用 file_id 上传链路。
- 仓库中未发现现成的通用反馈/投诉工单模块，本子任务需要新增最小主记录模型。
- 用户已确认 MVP 不需要双向聊天，不强制关联订单。
- `pages/user/index.vue` 与 `pages.json` 同时也是 Child A 的共享文件。

## Requirements

### R1. 数据模型
- 新增独立反馈主表即可，不扩展成消息子表或会话表。
- issue type 至少包含：
  - 功能建议
  - 功能异常
  - 体验问题
  - 订单问题
  - 其他问题
  - 投诉反馈
- status 至少支持：待处理 / 处理中 / 已回复 / 已关闭。
- 图片可直接存 file_id JSON 数组，不额外建图片子表。

### R2. 小程序用户侧能力
- “我的”页新增 `投诉/意见反馈` 入口。
- 新增反馈页，包含：
  - `我要反馈`
  - `反馈记录`
- 提交表单至少包含：issue type、content、image upload、mobile。
- 用户可查看自己的记录详情、处理状态、官方回复。

### R3. 商家后台处理能力
- 商家后台必须有反馈列表/详情（或抽屉）处理页。
- 至少支持：筛选、状态更新、官方回复编辑。
- `投诉反馈` 必须可单独筛选或被明显标记。

## Dependencies

### 逻辑依赖
- 不依赖 Child C。
- 不依赖 Child A 的业务逻辑完成，但复用 Child A 后稳定的“我的”页入口结构会更顺手。

### 文件级依赖
- 与 Child A 共享：
  - `yoshop2.0-uniapp/pages/user/index.vue`
  - `yoshop2.0-uniapp/pages.json`
- 协调要求：
  - 推荐在 Child A 落地后再启动 B；
  - B 必须基于最新文件形态追加反馈入口与页面注册，不能回退 A 已完成的隐私入口结构。

### 基础设施依赖
- 复用现有 `yoshop2.0-uniapp/api/upload.js` 上传能力。

## Acceptance criteria

- [ ] 用户可从“我的”页进入 `投诉/意见反馈` 页面。
- [ ] `我要反馈` 可提交 issue type、content、images、mobile，并具备基本校验。
- [ ] `反馈记录` 可查看自己的记录列表与详情。
- [ ] 详情页可看到处理状态、官方回复、更新时间等关键字段。
- [ ] 商家后台可查看记录、筛选 `投诉反馈`、修改状态并填写官方回复。
- [ ] MVP 仍保持单向工单模式，没有被扩成聊天系统。

## Rollback boundary

- 可通过隐藏“我的”页入口、后台菜单、路由来整体停用该功能。
- 新增反馈表与记录可保留，不影响订单/支付主链路。
- 即使后台处理页临时下线，也不应破坏已有订单或首页功能。

## Out of scope

- 用户与商家在工单内来回对话。
- 强制绑定订单。
- 推送通知、短信通知、客服聊天系统。
- 服务订单契约和首页弹窗配置。
