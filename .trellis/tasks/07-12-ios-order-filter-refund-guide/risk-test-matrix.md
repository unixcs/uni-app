# 风险与缺陷推演清单

## P0

1. unknown 被归入非 iOS，导致 Apple 订单走开发者退款。
2. 本地退款记录未创建，Apple 问询到达时系统错误建议退款或找不到订单。
3. Apple 回调认证/响应协议被 UI 改动连带破坏。
4. schema 未先发布，后端写新字段导致生产请求失败。
5. 渠道筛选在分页后执行，造成总数和跨页错误。
6. 并发本地申请或 Apple 自动建档产生多条活动退款单。
7. UNKNOWN 被当作退款安全结论并误调用开发者退款。
8. 回填覆盖在线写入的更强 Apple 证据，导致分类降级。

## P1

1. 本地申请刚提交即显示“Apple 处理中”，误导用户。
2. 多笔支付尝试选择错误交易。
3. 历史成功 iOS 单未回填，运营无法筛出。
4. 操作列 sticky 透叠或遮挡其他内容。
5. iOS 上传凭证仅前端隐藏但旧数据/提交 payload 导致异常。
6. 退款说明为空时阻止提交，但提示文案不清晰。
7. 列表查询新增不可索引 JSON 条件导致性能下降。
8. 两笔交易都成功时 loser 迟到回调污染 winner 分类。
9. 相同 create_time 缺少第二排序键导致跨页重复/遗漏。
10. Apple inquiry、取消/拒绝、最终成功乱序导致状态倒退。
11. 首次回填到后端上线之间的新交易漏分类。
12. iOS 页面隐藏上传入口但提交残留 images。

## P2

1. 教程标点、空格和术语不统一（Apple Store/App Store）。
2. 长文本在小屏换行不合理。
3. 详情按钮无 hover/focus 状态。
4. 其他订单标签页意外出现支付渠道筛选。
5. 重置后渠道值残留。

## Release Metrics

- 成功虚拟交易 `channel_class=UNKNOWN` 数量及最老时间；
- iOS 筛选命中真实订单；
- `/order/list` P50/P95；
- Apple inquiry 成功响应率和耗时；
- 重复 refund row 数量必须为 0；
- 前端退款页/订单详情 JS 错误数。
