## 5. 第二轮收口：退款认账与后台 trade 视图统一

### 为什么继续改
第一轮主要堵的是“支付成功但本地不认账”和“前台误判失败”。
第二轮排查发现，退款链路和后台详情还有一个共性问题：

- 系统很多地方还默认只看 `order.trade_id`
- 但虚拟支付切入后，同一订单可能存在多次支付尝试
- 一旦 `order.trade_id` 没及时挂到真正那笔 trade，上层就会出现“退款申请成功了，但状态没收口”或“后台看错支付信息”

### 本轮补的核心规则
- 退款发起时，不再死盯 `order.trade_id`，而是优先解析“这张订单真正该认的虚拟支付 trade”
- 退款收口时，不再默认拿 `order.trade_id` 查退款，而是按：
  1. 已绑定当前退款单的 trade
  2. 当前订单 trade_id
  3. 最近成功/已退款 trade
  4. 最近一次虚拟支付 trade
  依次兜底
- 后台订单详情，不再只拿 `order.trade_id` 那笔 trade 做虚拟支付摘要
- 后台完成服务时，补成先解析有效 trade，再决定是否发虚拟支付履约通知

### 直接收益
- 能降低样本 `10417` 这类“退款申请成功但本地状态还卡住”的概率
- 能降低样本 `10418` 这类“同单多次支付尝试，后台看不到正确 trade”的概率
- 后台详情页看到的支付信息，和后台按钮后续真正操作的 trade，更接近同一套来源

## 7. 实机退款已到账但前端仍显示“退款处理中”的根因与修复

### 用户实测订单
- 订单号：`332930560595366336`
- 本地 `order_id=10423`
- 退款单：`order_refund_id=10151`
- 支付交易：`trade_id=10266` / `out_trade_no=332930569128690632`

### 改前真实状态
- 用户已经收到退款金额
- 微信远端 `query_order.status=5`（已退款完成态）
- 但本地仍是：
  - `yoshop_order_refund.status=0`
  - `yoshop_order.order_status=10`
  - `payload_snapshot.virtual_refund.status=processing`
- 所以前端订单详情仍显示：`退款处理中`

### 根因
不是微信没退，也不是前端单纯展示错。
真正原因是：

- 虚拟支付退款在进入本地最终收口 `finalizeVirtualRefund()` 时
- 代码错误调用了 `Refund` service 自身并不存在的 `transaction()`
- 结果一到“该把退款单改成已退款”的最后一步就直接报错
- 于是出现“钱已经退到用户手里，但本地订单状态还停在退款处理中”

### 修复
- 文件：`yoshop2.0/app/common/service/order/Refund.php`
- 改动：把错误的 `$this->transaction(...)` 改成 `Db::transaction(...)`
- 这样退款完成态可以真正落库收口

### 修后验证
1. 先对用户实测单 `10151` 执行 `syncVirtualRefund(10151)`
   - 返回：`status=completed`
   - 远端状态：`virtual_status=5`
2. 再核对数据库：
   - `yoshop_order_refund.status=20`
   - `yoshop_order.order_status=20`
   - `yoshop_payment_trade.trade_state=30`
   - `payload_snapshot.virtual_refund.status=completed`
3. 再核对 API 投影：
   - `service_state_text=已退款`
   - `refund_info.service_state_text=已退款`

### 顺手补收的同类卡单
执行 `syncVirtualRefunds(10001)` 后，同类已到账未收口退款也被一并收回：
- `10417 / 332872263196571540` -> 已退款
- `10422 / 332930190680540241` -> 已退款
- `10423 / 332930560595366336` -> 已退款

### 结论
这次问题的本质不是“退款没成功”，而是“退款成功后的本地最后一步提交失败”。
这个口子补上后，后续同类虚拟支付退款单更容易自动从“退款处理中”收回到“已退款”。
